## What this is

The REST AI blog for `restai.ee`. REST AI means Responsible, Ethical, **Safe**
and Trustworthy AI. Safe, not Secure.

Purpose: AI GRCS awareness and education aimed at newcomers, building the

## Hard rules

**No em dashes or en dashes.** Anywhere. Use commas, colons or full stops.
Enforced by `scripts/check-style.sh`, which runs as step one of `make test`.

**No secrets in tracked files.** `.env` is generated by `scripts/init-env.sh`
and gitignored. Never print a secret to the terminal or paste one into a chat.
If the user must supply a credential, tell them which file to put it in.

**Test driven.** Write the failing check in `tests/acceptance.sh` first, then
make it pass. When adding a check, prove it works by planting the violation it
should catch and confirming it fails. A check that has never failed has never
been tested.

**Themes stay unmodified.** No AI generated themes, colours or typography. Every
colour, font and spacing value comes from the theme author. Themes are pinned
git submodules. If a theme must be changed, override it in
`site/layouts-hugoplate/` rather than editing the submodule, and say why in a
comment at the top of the override.

## Decisions already made, do not re-litigate

| Decision | Reason |
|---|---|
| PostgreSQL is the only database | User requirement. The site is static, so Postgres serves Listmonk alone |
| Not Ghost | Ghost supports MySQL 8 exclusively and dropped Postgres before 1.0 |
| Hugo, not Wagtail or Payload | Postgres capable CMSes have no theme pack, which would have forced inventing the design |
| Theme is Hugoplate | Congo was trialled and reverted, the user did not like it. Set in `.active-theme` |
| Single opt-in mailing list | Needs no SMTP relay, so the subscribe form works from day one |
| Capture subscribers, do not send yet | Campaigns come later, with double opt-in and a relay |

Full theme evidence, including every rejected candidate and why, is in
`docs/THEMES.md`.

## Architecture notes

- Builds run in a **pinned container** (`hugomods/hugo:debian-node-git-0.165.0`)
  as the host user, so nothing installs on the host and output is not root owned.
- Hugoplate is a **starter template on Hugo Modules**, not a self contained
  theme. Its modules are vendored to `site/_vendor` so builds are offline.
- Hugoplate overrides live in `site/layouts-hugoplate/`, mounted for that theme
  only via `[[module.mounts]]` in `site/config/themes/hugoplate.toml`. This keeps
  Congo and Blowfish on their own templates so the A/B comparison stays valid.
- Four no-op stubs in `site/layouts/_partials/` neutralise Hugoplate's
  unconditional calls to `gtm`, `adsense-script` and `cookie-consent`, so those
  modules are absent from the dependency tree rather than merely switched off.
- The subscribe form posts to `/subscribe`, which Caddy proxies to Listmonk, so
  it is same origin and readers never leave the site.
- Listmonk admin is loopback only and is not proxied. `/admin` must return 404.

## Traps already hit, do not repeat

**Anchor gitignore patterns.** An unanchored `data/` also matched Hugo's
`site/data/`, silently keeping `social.json` out of the repo and making the
footer social icons vanish on a fresh clone. Volume and build directories use a
leading slash (`/data/`, `/dist/`, `/backups/`). After changing ignore rules,
verify with a real fresh clone.

**Scan CSS, not just HTML, when checking what a page loads.** Font Awesome
pulled its webfonts from `cdnjs.cloudflare.com` through a `url()` inside a
stylesheet, invisible to an HTML only scan, while the site claimed to load
nothing third party. Fonts are now self hosted in `site/static/fonts`. The
acceptance check covers HTML and CSS.

**Do not invent the author's credentials.** `site/content/about.md` has a
placeholder block. It stays empty until he supplies real ones.

## Commands

```bash
make up        # postgres, listmonk, caddy
make build     # rebuild the site with the active theme
make test      # full acceptance suite, currently 24 checks
make ab        # build every candidate theme and serve side by side
make backup    # dump the subscriber database
```

Site on http://localhost:8080. Listmonk admin on :9000, loopback only, password
in `.env`.

## Before claiming something works

Run `make test`. Report failures with their output. If a step was skipped, say
so. Do not describe deployment as done: `docs/DEPLOY-HETZNER.md` is written but
has never been executed.
